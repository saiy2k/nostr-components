# Nostr Atlas crawler

Cloud Run jobs for backfill, frontfill, projection, and the URL activity sweep. This package is separate from the repo-root install.

- From `backend/`: `npm ci`, then `npm test`.
- Run projection after backfill or frontfill. Both write handle documents; projection consumes them.
- Deploy with `PROJECT_ID=nostr-components backend/deploy-nostr-atlas-backfill.sh`, `PROJECT_ID=nostr-components backend/deploy-nostr-atlas-frontfill.sh`, `PROJECT_ID=nostr-components backend/deploy-nostr-atlas-projection.sh`, and `PROJECT_ID=nostr-components backend/deploy-nostr-pulse-sweep.sh` from the repo root.
- Frontfill runs every hour as Cloud Run job `nostr-atlas-frontfill` (`0 * * * *` UTC, task timeout 25 minutes). It scans kinds 10011 and 0 on `relays.json` forward from `syncedUntil`, overlapping the previous hour by 15 minutes. State stays in `relayCrawlerState` with prefix `frontfill`, separate from finished backfill cursors. `nextRelayIndex` on `frontfill-run` is written before each relay is fetched. A soft deadline (`FRONTFILL_RUN_DEADLINE_MS`, 20 minutes) stops new cursors and finishes the one in flight. The 90-day gap is a one-time walk down to a floor stored on first create; it runs only after that relay/kind's live window is complete, and setting `FRONTFILL_INITIAL_LOOKBACK_SECONDS=0` stores no gap. Size the lookback before the first deploy to cover the time since backfill finished. The floor does not move later; delete the `frontfill:` state docs to re-seed. The daily backfill job stays for history that is not finished.
- Projection runs every hour at half past (`nostr-atlas-projection-hourly`, `30 * * * *` UTC) and pauses `nostr-atlas-projection-daily`. It selects pending handles by `pendingClaimCount` and `nextAttemptAt`, so frontfill claims are included. A lease on `relayProjectionRuns/lease` is renewed as the run writes and cleared on exit. A second execution exits without writing while the lease is held.
- The pulse sweep runs every 10 minutes as Cloud Run job `nostr-pulse-sweep`. It reads the rendezvous relays plus `sweepExtra` and writes `nostrUrlActivity` (with `reactions` and `recipients`), `nostrUrlZaps`, `nostrUrlDomains`, and `nostrPulseSweepState`. Ingest keeps each pubkey's newest web reaction and counts a zap receipt only after the NIP-57 check. Repeats are no-ops. Reaction documents store `pubkey`. Each sweep also copies that field from the document id onto reactions that were stored without it, one page at a time, until that pass is done. A failure in that pass is logged and does not stop the relay sweep. A provider check that is still failing on the third try is left unstored so one address cannot stall the job. A second that does not fit in one page is stored on that cursor as `lastGap`. A sweep writes a cursor only when its stored revision still matches the one it read, so an overlapping run cannot roll that cursor back. Deploy the sweep only when asked.
- `nostr-pulse/import-web-pulse.js` is a local one-time import, not a Cloud Run job. It only reads document ids from `Nostr_reactions` and `Nostr_zaps` in project `sat-the-standard`. It does not read `Nostr_urls`, `Nostr_domains`, or `Nostr_syncState`, and it never writes to `sat-the-standard`. A dry run is the default and writes nothing, including profiles. `--write` sends events it still finds on relays through `ingestUrlEvent` into project `nostr-components`.
- At the end of each sweep, `nostr-pulse/rollup.js` folds URL totals into `nostrUrlDomains` and the site-wide totals on `nostrPulseSweepState/rollup`. It pages by `updatedAt` and commits at most one batch a second. It does not write `updatedAt`. A hidden URL stays out of its domain. A hidden domain keeps its own totals and stays out of the site-wide totals.
- The same run fetches profiles for up to 200 new reactors and zappers, tracked as `url-actor`. Anonymous zaps have no sender, so they are skipped. A profile failure is logged and does not stop the sweep.
- Hide a domain or URL with `node nostr-pulse/hide.js <domain or URL>` from `backend/`, and show it again with `--show`. `node nostr-pulse/hide.js --rebuild <domain>` recomputes that domain from its visible URLs. Rebuild and the sweep rollup share a lease. Each run has its own token and renews it on every write, so an overlapping run or an expired lease cannot commit late totals. A rebuild stages the next URL markers, then publishes the domain totals and that marker epoch in one transaction. The sweep ignores a staged marker until that epoch is published, so a failed rebuild cannot leave the next sweep to count those URLs twice or to skip them. A rebuild waits while a rollup is running, and a sweep skips its rollup while a rebuild holds the lease. Set `hidden` with the script, not in the console. A console edit hides the row from lists but leaves its numbers in the totals until a rebuild.
- Client Firestore rules are [firestore.rules](firestore.rules), deployed only with:

```sh
firebase deploy --only firestore:rules --project nostr-components \
  --config backend/firebase.json
```

- Deploy those rules to `nostr-components` only. Leave `sat-the-standard` alone. A root `firebase deploy` does not include this file.
- Job behavior, scheduler, and IAM: [README.md](README.md).
- NDK is created only in `nostr-atlas/ingestion.js`. NDK and the claim pool open sockets through `PublicWebSocket`, which refuses a host that resolves to a private address.
- Projection stores signed kind 0 and kind 10002 profiles in `nostrProfiles`, including relay hints and the zap provider. New claim writes leave zap fields off the directory claim. `lookupAtlasHandle` reads `nostrProfiles.zap` when that document exists and the claim fields until then, so deploy that function with this crawler.
- Directory identities refresh every 24 hours. A verified handle with no `nostrProfiles` document is due immediately, including identities imported without a claim queue. The pass also stores `xPicture` when the signed profile has no picture.
- NIP-05 and X bio fetches go through `fetchPublicHttps`. Relay health is written once per run to `nostrRelayHealth`, keyed by the sha256 of the normalized relay URL.
- Profile refresh replaces `zap-pass.js`, `nip05-backfill.js`, `picture-backfill.js`, and `kind0-metadata-backfill.js`.
